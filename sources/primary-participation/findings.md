# March 3, 2026 primary participation

Acquired public county aggregate **ballots cast by party**, including every voting mode, for **4,351 native 26P precincts across eleven counties**. This expands the original six-county / 1,159-precinct edition. Every included row joins to the expanded dashboard reference; incomplete groups stay unclassified. No candidate-vote sum is used as a participation proxy, no votes are allocated by geographic area, and no voter-level records were fetched or retained.

Counts above are only ballots assigned to verified native precincts. Bexar unmatched records, Collin limited-ballot records, and the Collin county-summary discrepancy described below are excluded. **Meaning:** Democratic share = Democratic primary ballots / (Democratic + Republican primary ballots). This describes participation in these two primaries, not party registration, individual affiliation, or November vote choice. Common geographic groups require every current precinct’s complete Democratic and Republican counts. The Rust engine should sum numerator and denominator before taking the percentage; use missing data for unsupported precincts/groups.

## Coverage limits

The [TLC comprehensive election collection](https://data.capitol.texas.gov/dataset/comprehensive-election-datasets-compressed-format) exposes historical data through 2024. The current 26P release supplies boundaries, not a statewide 2026 party-participation file. The inspected current CKAN catalog is cached.

**Travis and Bell:** the official Clarity March 3 portals provide combined precinct turnout but no verified party-specific ballot totals. Their candidate returns do not supply a complete under/overvote accounting and cannot safely replace participation counts; some candidate cells are privacy-protected. Candidate values were not reconstructed from protected cells. Current inspection found no aggregate alternative meeting the required scope. **Hockley:** the official elections page posts party election-night summaries but no acquired precinct party-ballot table. Those three counties are explicitly unavailable in this dataset. This is a bounded acquisition result, not a claim that records cannot exist elsewhere.

## Rebuild and validation

Run `uv run dashboard/scripts/build_primary.py --offline` after acquisition, then `python dashboard/tests/verify_primary.py`. The small Madison bound transcription is tracked; raw public reports can be reacquired with the online builder. Without `--offline`, only missing public aggregate inputs are downloaded; existing source snapshots are preserved. The script requires Poppler’s `pdftotext`, and declares its HTTP dependency. Versioned Clarity URLs reproduce the downloaded snapshots; the cached PDFs and hashes preserve county publications that may later change.

`dashboard/data/primary.json` matches the existing demographic engine’s schema. Every source’s exact URL, local path and SHA-256 are embedded. `validation.json` records county controls, missing/native coverage, complete-group counts, source exclusions and output hash. The verification checks all raw-source hashes, native IDs, integer count integrity, county controls, incomplete coverage, Hays special-ballot reconciliation, Madison’s bound transcription, and complete-group counts.

`dashboard/tests/primary_expansion.py` independently checks every county/day/cohort primary point and bucket, newly covered county daily/cumulative comparisons, future-day missingness, actual browser views and CSV exports. The shared reader supports both native APIs and content-addressed Pages artifacts.
