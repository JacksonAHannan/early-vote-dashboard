# County source recovery: Montgomery and five SOS counties

Checked October 26, 2026. This note distinguishes a downloadable official roster from proof that a day or precinct is complete. Voter identities, names, addresses, CSV/ZIP/XLSX/PDF roster bytes and extracted roster text were handled only in memory or anonymous pipes. Persisted artifacts contain source URLs, hashes, dates, aggregate counts and schema diagnostics only. The investigation itself made no production changes; the parent integration retains the reviewed aggregate outputs.

The machine-readable evidence is [county-source-probes.json](../../analysis/county-recovery/county-source-probes.json). The implemented collector is [collect_county_native.py](../../dashboard/scripts/collect_county_native.py); its synthetic tests are [test_county_native.py](../../dashboard/tests/test_county_native.py).

## Findings and usable scope

- Montgomery has official weekend data. Its county adapter fails at a real blank-identifier ordinary-E voter record on October 24, which prevents the existing all-days request from returning later days. Quarantining only residence precinct 110 on that date preserves the other 120 native precincts and permits October 25 to be collected.
- Waller, Washington and San Patricio publish county-native daily rosters that recover substantial data absent or sparse in SOS exports. Native county and SOS totals can differ; these are parallel official administrative sources, not interchangeable completeness controls.
- Navarro October 25 currently returns HTTP 200 with an empty body, and Starr October 23 contains mail-only rows. Those observations establish missing in-person data, not zero voting. No additional current county-native source for those missing dates was discovered in the bounded official-page search.
- No county-native collector output self-certifies completion or fills an absent precinct with zero. Unknown source precincts are retained in `UNASSIGNED`, preventing them from certifying native precinct zeros. Identified ambiguity quarantines only affected precinct/date cells.

## Montgomery: confirmed collector failure

[Official roster landing](https://elections.mctx.org/evRoster.asp?ELID=97&curLang=English), [October 24 ZIP](https://elections.mctx.org/EVHistoryFiles/GEN110326_10.24.2026.zip), [October 25 ZIP](https://elections.mctx.org/EVHistoryFiles/GEN110326_10.25.2026.zip), [county vendor daily aggregate graph](https://updates.electionlink.net/widgets/montgomerytx/2026-11-03/EarlyVotingGraphs.html), and [vote-type definitions](https://elections.mctx.org/pdf/rosterfileinstructions.pdf).

October 24 ZIP SHA256 `c79ba9068070dcbb931109e4ab054d53c9790ce36f56557dfc1da743ac653ea4` contains 48,620 rows: 48,233 E, 72 L and 315 A. There are 16,360 distinct nonblank ordinary-E identifiers. Three E rows lack VUID and all have residence precinct 110. These are populated voter rows, not a footer or a header alias: LastName, FirstName, MiddleName, Voting_Precinct, DateVoted, VoteType, Election_Name and CountyElectionPrecinct are populated. Every field is identical among those three rows except Election_Name. No matching nonblank-ID E signature occurs in the same daily file. This is consistent with one voter copied across three jurisdictions, and adding one would match the graph total 16,361; that is an inference, not an identity guarantee. The conservative implementation should not invent an identifier.

Precinct 110 contains 148 identified E voters plus those ambiguous rows. Withholding that entire precinct/date cell retains **16,212** identified E voters on October 24. Reference geography has 68 common groups and 55 exact pairs; 110 is its own exact old-110/new-110 group. Thus a cumulative week can preserve 67 groups and 54 exact pairs; October 25 alone can retain all 68/55 where both-year counts are present. These are maximum geography counts, not a claim of independently certified reporting completeness.

October 25 ZIP SHA256 `30b2bf65d47985f9328f89ce3064bbdc09689d741835c38fef2f242357aaa520` contains 9,176 distinct ordinary-E IDs, no blank E IDs and no within-file precinct/date conflicts, matching the graph 9,176. October 19–23 likewise have no blank E IDs. The matched 2024 roster scope is ordinary E only, excluding L and A, with existing cross-date identity deduplication and historical graph discrepancies retained. The matched 2024 October 21–27 cache totals are 16,519; 17,015; 18,302; 19,069; 20,102; 23,423; 12,920. These historical Montgomery totals were inspected from existing aggregate caches rather than freshly re-downloading all seven historical rosters. Historical official URLs use `https://elections.mctx.org/EVHistoryFiles/GEN110524_10.21.2024.zip` through `10.27.2024.zip`; the [2024 graph](https://updates.electionlink.net/widgets/montgomerytx/2024-11-05/EarlyVotingGraphs.html) is a separate administrative control.

## Implemented recovery contract and checks

`python dashboard/scripts/collect_county_native.py --county {waller,washington,sanpatricio} --through 2026-10-25` discovers only the official page’s advertised general-election daily links, downloads through the existing anonymous-pipe transport, parses PDF text through `pdftotext` or streams XLSX XML from an in-memory ZIP, and emits only aggregate Daily JSON on stdout. Diagnostics on stderr are dates and exception classes, never response bodies or rows. Only completed Central-time calendar days are included. A missing or unparseable file is omitted, never a zero day. Every Daily preserves the encoded official URL and raw SHA256, `complete:false`, source qualification, `unavailable_precincts`, and any unassigned-label explanation. Missing native precincts are not filled with zero.

Within-day repeated identifiers in the same precinct are counted once. A blank identity with a known precinct quarantines that precinct/date. Different dates or precincts sharing an identity quarantine every affected cell. No fallback identity based on names or addresses is invented. Root owns Rust integration, broader quality certification, matched-group aggregation and any later production refresh.

Verification: `python -m unittest discover -s dashboard/tests -p test_county_native.py -v` passed all 13 synthetic tests, and `python -m py_compile dashboard/scripts/collect_county_native.py` exited 0. Tests cover date/scope validation, mixed-case PDF headers, headerless sparse XLSX, preserving split labels until official evidence, accepted and rejected alias joins, duplicate handling, blank IDs, local cross-date quarantine, unknown-label `UNASSIGNED`, and separating mail NONE labels from actual in-person links. Live CLI verification for all three counties returned all seven completed dates; final aggregate output and source hashes are in the evidence JSON. County roster completion remains explicitly unverified against an independent all-check-in control.


Final review also verifies that wrong election hosts/paths and Washington filename/date mismatches are rejected, duplicate ambiguous links withhold only that date, failed downloads/parses preserve unrelated dates, Central-time active voting days are excluded, and San Patricio page footers cannot be parsed as blank-identifier voters. The finalized three-county live Rust bridge returned the same seven dated aggregate totals as the accepted edition.
