# Recurring large-county precinct refresh

Reviewed October 28, 2026 against the pinned nine-day production snapshot in `analysis/refresh-reliability/baseline-data.json`. This change updates production collectors; it does not add a dated recovery manifest or overwrite any production cache.

## Production changes

- **Cameron:** `collect_large_county_refresh.py` discovers the current county-wide in-person workbook from the official results landing on every run. It validates the election, individually dated sections and each CHECK-IN date. It retains successful sections independently when another section is malformed, deduplicates identities globally, quarantines affected cells, and never infers absent cells or days as zero. The Rust adapter compares each dated native alternative with its dated SOS alternative using the existing native-coverage selector and independent qualification rules. Earlier stronger SOS observations remain selected.
- **Denton:** the same production collector discovers the current Daily In-Person Early Voting Roster on every run. Its `Time` field is a complete Excel timestamp. Its `Precinct` field contains six-digit subdivisions, which are **not** native four-digit map precincts. Every refresh re-downloads all published same-date SOS identity sources, proves only exact full-label aliases through globally unique native identities and unique same-date SOS identities, and includes foreign and conflicting targets before accepting an alias. No digits are truncated. A new contradictory target revokes the alias and withholds all possibly affected native cells. A failed identity-proof download rejects the new native candidate, retaining dated SOS and previously successful observations instead of certifying aliases from reduced evidence. All input hashes participate in the derived aggregate hash.
- **Shared native aggregation:** an unposted newest day no longer causes otherwise valid observed days to be discarded. This fixes `days_from` and both branches of `CountyRoster.days`, which serve multiple county formats. An empty roster still fails; missing days remain absent.
- **Travis:** missing or invalid individual ZIP-day members no longer discard successful independent days. Parsing and cross-day identity validation commit only after the entire dated workbook passes, so a failed member cannot poison later dates.
- **Montgomery:** failed individual dated downloads or parsers no longer discard every other day's update. Identity and blank-ID quarantine changes commit transactionally only after the entire dated CSV passes. Provenance remains specific to each successful date.
- **Completion controls / Dallas:** historical SOS fallback no longer overwrites previously reviewed native county controls before a native job that may fail. Fresh SOS editions continue to replace older SOS-only controls; fresh successful native jobs retain priority over both. Dallas's 2024 aggregate archive is now optional: a checkout without the original project's local file downloads and validates the same official date/location workbook through the existing transport. Precinct-source equality and zero qualification remain strict.
